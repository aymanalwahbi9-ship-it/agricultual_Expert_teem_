# تصميم نظام الخبير الزراعي

## 1. الغرض من الوثيقة

تحدد هذه الوثيقة التصميم العام لنظام الخبير الزراعي، وتحول نتائج وثيقتي المتطلبات وتحليل حالات الاستخدام إلى بنية قابلة للتنفيذ باستخدام Laravel وBlade وTailwind CSS. تركز الوثيقة على مكونات النظام، ومسؤولية كل مكون، ومسار البيانات، وقواعد دمج نتائج الصورة والتربة والمعرفة.

لا تحدد هذه الوثيقة تفاصيل التنفيذ البرمجي الدقيقة. وتُستخدم أساسًا لإعداد تصميم قاعدة البيانات، والمخططات، وواجهات النظام، ثم تنفيذ المكونات واختبارها بصورة تدريجية.

## 2. قرارات التصميم الرئيسية

| القرار | التصميم المعتمد | السبب |
|---|---|---|
| نمط التطبيق | تطبيق ويب Laravel | يدعم بناء الواجهات والخدمات وقاعدة البيانات ضمن بنية واحدة قابلة للتوسع |
| واجهة المستخدم | Blade مع Tailwind CSS واتجاه RTL | مناسبة لواجهة عربية واضحة وسريعة التطوير |
| نمط النظام | بنية طبقية بسيطة | تفصل العرض عن منطق التطبيق والبيانات وتسهّل الاختبار |
| تحليل الصورة | مكوّن محاكاة في الإصدار الحالي | يحافظ على مسار التكامل دون الحاجة إلى نموذج مدرّب |
| قراءة التربة | إدخال يدوي أو محاكاة | يتيح اختبار النظام دون حساس فعلي |
| قاعدة المعرفة | بيانات محلية منظمة | تضمن استمرار البحث دون اتصال خارجي |
| القرار النهائي | نتيجة إرشادية مفسّرة | تمنع عرض المحاكاة أو البيانات الناقصة كتشخيص قطعي |
| التخزين | قاعدة بيانات علائقية | مناسبة للمحاصيل والحالات والقواعد والسجلات والعلاقات بينها |

## 3. حدود النظام

### 3-1 ما يدخل داخل النظام

يدخل داخل النظام ما يلي:

- الواجهة العربية واختيار المحصول.
- إدخال صورة النبات والتحقق من الملف.
- مكوّن تحليل الصورة المحاكى.
- إدخال قراءات التربة أو توليدها في وضع المحاكاة.
- تصنيف عناصر التربة وفق قواعد المحصول.
- البحث في قاعدة المعرفة المحلية.
- دمج نتائج الصورة والتربة والمعرفة.
- عرض النتيجة والتوصية والمصدر ودرجة الثقة.
- حفظ سجل العمليات وإنشاء تقرير التربة.
- المركز التعليمي.

### 3-2 ما يبقى خارج الإصدار الحالي

لا يشمل الإصدار الحالي تدريب نموذج تعلم آلي فعلي، أو الاتصال المباشر بحساسات ميدانية، أو إصدار تشخيص مخبري، أو تقديم علاج قطعي، أو إدارة حسابات متعددة ولوحة إدارة متقدمة.

## 4. البنية العامة للنظام

يعتمد النظام على أربع طبقات مترابطة:

| الطبقة | المسؤولية | أمثلة على المكونات |
|---|---|---|
| طبقة العرض | عرض الصفحات واستقبال مدخلات المستخدم | Blade Views، النماذج، مكونات Tailwind |
| طبقة التطبيق | تنسيق حالات الاستخدام والتحقق من المدخلات | Controllers، Form Requests، Services |
| طبقة القرار | تحليل المدخلات وتطبيق القواعد ودمج النتائج | Image Analysis Service، Soil Analysis Service، Decision Engine |
| طبقة البيانات | حفظ واسترجاع المعرفة والسجلات | Eloquent Models، Repositories، قاعدة البيانات |

تتواصل الطبقات عبر واجهات واضحة. ولا ينبغي لصفحات Blade أن تطبق قواعد القرار مباشرة، كما لا ينبغي لمحرك القرار أن يعتمد على تفاصيل العرض.

## 5. مكونات النظام

### 5-1 الواجهة العربية

تقدم الواجهة الصفحة الرئيسية، واختيار المحصول، ونماذج تحليل الصورة والتربة، وصفحة البحث، وصفحة النتائج، والسجل، والمركز التعليمي. يجب أن تعمل الواجهة باتجاه من اليمين إلى اليسار، وأن تعرض رسائل التحقق والتنبيهات بلغة واضحة.

### 5-2 وحدة إدارة الحالة

تنشئ الوحدة حالة تحليل جديدة، وتحفظ المحصول والمدخلات المتوفرة ومصدر كل مدخل. تسمح الحالة بتشغيل تحليل الصورة فقط، أو تحليل التربة فقط، أو تشغيل التحليل المدمج عند توفر المصدرين.

### 5-3 خدمة تحليل الصورة

تستقبل الخدمة صورة صالحة، وتعيد نتيجة محاكاة تتضمن الحالة المحتملة، ودرجة الثقة، والصفات المرئية. تُصمم الخدمة بواجهة مستقلة حتى يمكن استبدال المحاكاة بنموذج فعلي مستقبلًا.

### 5-4 خدمة تحليل التربة

تستقبل الخدمة قيم النيتروجين والفوسفور والبوتاسيوم ودرجة الحموضة والرطوبة ودرجة الحرارة، بالإضافة إلى مصدر القراءة ووقتها. تتحقق الخدمة من النطاقات، ثم تصنف كل عنصر إلى منخفض أو مناسب أو مرتفع وفق قواعد المحصول.

### 5-5 خدمة قاعدة المعرفة

تبحث الخدمة في الحالات والأعراض وقواعد التربة والتوصيات والمصادر. تبدأ عملية البحث بتصفية النتائج حسب المحصول، ثم تطبق المطابقة بالكلمات المفتاحية والمرادفات، ثم ترتب النتائج حسب درجة الارتباط وموثوقية المصدر وحداثة المراجعة.

### 5-6 محرك القرار

يستقبل المحرك نتائج الوحدات المستقلة، ويتحقق من كفاية البيانات ودرجة الثقة، ثم يحدد المؤشرات المتفقة والمتعارضة. يعيد المحرك نتيجة مفسرة لا تتضمن توصية إلا إذا كانت مرتبطة بمصدر موثق.

### 5-7 خدمة السجل والتقارير

تحفظ الخدمة ملخص كل عملية، وتتيح إعادة فتح النتيجة أو حذفها. كما تنشئ تقريرًا منظمًا لقراءات التربة وحالات العناصر والتوصية الأولية ومصدر القراءة.

## 6. تدفق البيانات الرئيسي

يمر التحليل المدمج بالخطوات الآتية:

1. يختار المستخدم المحصول ونوع العملية.
2. يستقبل النظام الصورة أو بيانات التربة أو كليهما.
3. يتحقق النظام من اكتمال المدخلات وصحتها.
4. تحلل خدمة الصورة الصورة أو تعيد نتيجة المحاكاة عند تفعيل الوضع التجريدي.
5. تحلل خدمة التربة القيم أو تولد قراءة محاكاة.
6. تسترجع خدمة المعرفة الحالات والقواعد المرتبطة بالمحصول والمؤشرات.
7. يرسل النظام النتائج المستقلة إلى محرك القرار.
8. يقارن محرك القرار درجات الثقة ومؤشرات الاتفاق والتعارض.
9. يعرض النظام النتيجة والتوصية والمصادر والتنبيه المناسب.
10. يحفظ النظام ملخص العملية في السجل.

## 7. تصميم نتيجة القرار

يجب أن تكون نتيجة القرار موحدة مهما كان مصدرها. يتكون نموذج النتيجة من العناصر الآتية:

| العنصر | الوصف |
|---|---|
| نوع العملية | صورة، تربة، بحث معرفي، أو نتيجة مدمجة |
| المحصول | المحصول الذي بُني عليه التحليل |
| الحالة المحتملة | المرض أو الآفة أو نقص العنصر أو الحالة غير الحاسمة |
| درجة الثقة | قيمة تقريبية مع تصنيف مفهوم للمستخدم |
| المؤشرات المؤثرة | الأعراض أو قيم التربة أو نتائج البحث |
| التعارضات | اختلافات بين المصادر إن وجدت |
| التوصية | توصية مرتبطة بمقطع معرفة موثق، أو رسالة عدم كفاية |
| المصدر | مصدر المعرفة وتاريخ مراجعته |
| التنبيه | يوضح أن النتيجة إرشادية وليست تشخيصًا نهائيًا |

## 8. قواعد التعامل مع الثقة والتعارض

### 8-1 الثقة المقبولة

إذا تجاوزت النتيجة عتبة الثقة المحددة في إعدادات النظام، يمكن عرضها بوصفها نتيجة أولية، مع إبقاء التنبيه الإرشادي ظاهرًا.

### 8-2 الثقة المنخفضة

إذا كانت درجة الثقة أقل من العتبة، يعرض النظام النتيجة بوصفها غير حاسمة، ويطلب صورة أوضح أو بيانات إضافية، ولا يصدر توصية قطعية.

### 8-3 نقص البيانات

إذا كانت البيانات الإلزامية ناقصة، يوقف النظام التحليل ويحدد الحقل المطلوب. وإذا كانت البيانات الاختيارية غير متوفرة، يمكن للنظام تنفيذ تحليل جزئي مع توضيح حدوده.

### 8-4 تعارض الصورة والتربة

إذا أشارت الصورة إلى حالة مرضية بينما أشارت التربة إلى نقص غذائي محتمل، يعرض النظام المصدرين منفصلين، ويحدد التعارض، ويقدم الحالة أو الحالات الأقرب وفق القواعد المتاحة دون إخفاء أي مؤشر.

### 8-5 عدم كفاية المعرفة

إذا لم يجد النظام مقطع معرفة موثقًا بدرجة ارتباط كافية، يعرض النتيجة المتاحة مع رسالة عدم كفاية المعرفة، ولا ينشئ توصية جديدة من عنده.

## 9. الواجهات الرئيسية

| الواجهة | الوظيفة الأساسية |
|---|---|
| الصفحة الرئيسية | الوصول إلى التحليل والبحث والسجل والتعليم |
| اختيار المحصول | تحديد المحصول قبل تنفيذ العملية |
| تحليل الصورة | رفع الصورة أو اختيارها وتشغيل التحليل |
| تحليل التربة | إدخال القيم أو تفعيل المحاكاة |
| نتيجة التحليل | عرض النتيجة والأسباب والثقة والمصدر والتنبيه |
| البحث المعرفي | البحث عن حالة أو عرض أو توصية موثقة |
| السجل | عرض العمليات السابقة وإعادة فتحها أو حذفها |
| المركز التعليمي | شرح النظام ومسار البيانات وقاعدة المعرفة |

## 10. قرارات قابلية التوسع

تستخدم خدمة تحليل الصورة واجهة مستقلة عن طريقة التحليل. لذلك يمكن استبدال المكوّن المحاكى بنموذج فعلي دون تغيير صفحات النتائج أو سجل العمليات.

وتستخدم خدمة التربة كائن قراءة موحدًا يحتوي على القيم والمصدر والوقت وحالة الجودة. لذلك يمكن إضافة حساس فعلي مستقبلًا دون تغيير محرك القرار.

ويستقبل محرك القرار نتائج معيارية من المصادر المختلفة. لذلك يمكن إضافة مصدر جديد، مثل بيانات الطقس، بشرط أن يعيد نتيجة متوافقة مع نموذج القرار.

## 11. التحقق والاختبار التصميمي

يجب أن يغطي الاختبار التصميمي الحالات الطبيعية والاستثنائية. وتشمل المجموعة الأولية الحالات الآتية:

| الحالة | النتيجة المتوقعة |
|---|---|
| صورة صالحة وثقة مرتفعة | عرض نتيجة أولية مع الأسباب والمصدر |
| صورة غير صالحة | رفض الصورة وطلب ملف بديل |
| صورة بثقة منخفضة | عرض نتيجة غير حاسمة وطلب بيانات إضافية |
| قيم تربة صحيحة | تصنيف العناصر وإظهار التوصية الأولية |
| قيمة تربة خارج النطاق | رفض القيمة وشرح التصحيح المطلوب |
| تحليل دون معرفة كافية | عرض رسالة عدم كفاية المعرفة |
| اتفاق الصورة والتربة | عرض نتيجة مدمجة أكثر اتساقًا |
| تعارض الصورة والتربة | عرض التعارض ومنع القرار القطعي |
| انقطاع الإنترنت | استمرار البحث المحلي ووضع المحاكاة |
